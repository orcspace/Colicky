# Статус восстановления

## Получено

Восстановлены C#-файлы семи собственных DLL из HeyClicky Windows 1.1.3, JavaScript движка рисования, расширение Chromium, шрифты, звуки, изображения и встроенные клиентские ресурсы. Источник и SHA-256 зафиксированы в `scripts/recover.py` и `recovery.json`.

## Проверки

Все семь модулей успешно скомпилированы локально с SDK .NET 10.0.100, target framework `net9.0`, C# 14. Основная команда:

```text
dotnet build Source/HeyClicky/HeyClicky.csproj -m:1 -nr:false
```

Проекты связаны через `ProjectReference`; собственные модули собираются из кода. Сторонние managed DLL берутся из `.cache/original/lib/app`. Предупреждения анализаторов и nullability пока остаются. Сборка не приравнивается к подтверждению корректности каждой функции.

Windows-проверка [40556160699](https://github.com/orcspace/Colicky/actions/runs/40556160699) успешно завершила сборку всех семи модулей, smoke-проверки, подготовку runtime и 12-секундный запуск процесса в изолированном demo-режиме. Это проверка запуска процесса, а не визуальная или полная end-to-end проверка. После этого отдельно исправлена запись результата клонирования колонок dashboard; локальная повторная сборка прошла.

GitHub Actions повторяет восстановление и выполняет Windows-сборку. Актуальный результат и диагностика доступны в Actions; учитывайте SHA проверенного коммита. Smoke-программа проверяет SSE на разрезах UTF-8/CRLF, финальную строку без перевода строки и классификацию URL.

## Исправления

- ILSpy 11.2 восстановил большинство конструкций точнее; 9.1 дополняет пустые или пропущенные файлы.
- Удалены атрибуты повторной генерации `GeneratedRegex` и `LibraryImport`: их готовые реализации уже есть в извлечённом коде.
- Исправлены ссылки и scope локальных функций, скобки `with`, конфликт локальных имён и ref-local initializer.
- Исправлены конкретные присваивания после клонирования записей. Часть `init` заменена на `set`, что ослабляет ограничение публичного C# API, сохраняя последовательность обнаруженных в IL операций. Это требует последующей проверки поведения.
- Восстановлены несколько потерянных элементов inline arrays, шейпинг ключа шрифта, квалификация enum Blend, definite assignment и ограничение required полей PenStroke в восстановленных вызовах.
- Скрипт ремонта проверен на повторное применение: второй запуск не изменяет результат.

## Как запустить

На Windows x64 выполните `scripts/build.ps1 -Prepare`, затем `scripts/build.ps1 -Launch`. Скрипт получает полный проверенный runtime, собирает собственные модули и копирует семь собранных DLL поверх runtime в `artifacts/runtime`.

Apphost EXE, нативные DLL, runtime .NET, PRI/XBF и прочие скомпилированные ресурсы остаются исходными. Процесс в demo-режиме успешно оставался запущенным 12 секунд в Windows CI. Видимый интерактивный UI, GPU, микрофон, браузерное расширение, update flow и end-to-end AI-поведение ещё не подтверждены.

## Что нельзя восстановить из данного установщика

Серверный Worker, базу данных, ключи серверных провайдеров, Git-историю, комментарии и полный исходный XAML. Клиентские классы auth, billing, realtime и интеграций содержат протокол, но не серверную реализацию. Для независимого продукта потребуется собственный backend и проверка всех API-контрактов. Подписку или авторизацию восстановление не обходит.
